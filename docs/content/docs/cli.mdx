`yaksh` is a command-line client for the Yaksh API. Coding agents, CI and persons use the same commands. The `agent`, `scenario`, `persona`, `run`, `suite` and `conversation` commands write the JSON of the server to stdout. With `--wait`, `yaksh run start` waits for the calls and then for the judges. Then it writes the run.

`yaksh auth status`, `yaksh version` and `yaksh scenario generate` write JSON that the CLI makes. `yaksh guide` writes Markdown. `yaksh auth login` and `yaksh auth logout` do not write to stdout. Each command writes progress, hints and errors to stderr. Each command exits with 0 if it has no error, and with 1 if it has an error. If a test ran and did not pass, the last lines start with `failed:` and `next:`. If the command itself went wrong, the line starts with `error:`.

## Install

Install the CLI on macOS or Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/plivo-labs/yaksh/main/install.sh | bash
export PATH="$HOME/.yaksh/bin:$PATH"   # also add this line to your shell profile
```

The script installs the newest release in `~/.yaksh/bin`. It checks the download against the checksums of the release. To install one version, set `YAKSH_VERSION`, for example `YAKSH_VERSION=0.2.1`. To install in a different folder, set `YAKSH_INSTALL_DIR`.

You can also give this text to your coding agent. It installs the CLI and its skill:

```text
Install the Yaksh CLI with
curl -fsSL https://raw.githubusercontent.com/plivo-labs/yaksh/main/install.sh | bash,
then run npx skills add plivo-labs/yaksh -g
and follow the yaksh skill to test my voice agent.
```

### Updates

The CLI keeps itself at the version of the server. Before each command that uses the server, it reads the version of the server. If the minor version of the server is different, the CLI changes itself to the newest release of that minor version, then does the command again. One time each day, it also gets a newer patch of its minor version. The `auth` commands do not update the CLI.

If the CLI cannot update itself, it writes a warning and does the command. For example, this occurs when it cannot write to its folder, or when no release of the CLI has the minor version of the server.

### Build from the source code

A CLI that you build from the source code has the version `dev`. It never updates itself. At the root of a clone of the repository, build it with Go 1.27 or later:

```sh
cd cli && go build -o ~/.yaksh/bin/yaksh .
```

## Log in

```sh
yaksh auth login --server http://localhost:8000
```

The command asks for the API token: the value of `YAKSH_API_TOKEN` on the server. It does a check of the server and the token. Then it saves them. Without a terminal, send the token on stdin with `--with-token`. `yaksh auth status` shows the server. It also shows if the server accepts the token.

You can also set two variables and not use `yaksh auth login`, for example in CI. Set `YAKSH_URL` to the URL of the server without `/api/v1`, for example `http://localhost:8000`. Set `YAKSH_API_TOKEN` to the token. If you set `YAKSH_URL` or `YAKSH_API_TOKEN`, the CLI uses that variable and not the saved value.

## Add scenarios

```sh
yaksh scenario create --agent <agent id> -f move-appointment.yaml
```

This command adds a scenario from a YAML or JSON file with the fields of a scenario: `name`, `persona_id`, `instructions`, `data_sets` and `criteria`, and if you need them `category`, `description`, `unknown_facts`, `first_words` and `caller`. `yaksh scenario view` shows these fields, and `yaksh persona list` shows the IDs of the personas. The CLI sends each value as the file writes it. Thus a date such as `2027-01-15` and a code such as `0042` do not change. For what to write, refer to [Writing instructions](/docs/writing-instructions) and [Writing criteria](/docs/writing-criteria).

- `yaksh scenario update <scenario id> -f <file>` changes the fields that the file holds. A list in the file replaces the whole list. Keep the `id` of each data set that stays: a data set without an `id` is a new data set.
- `yaksh scenario generate --agent <agent id> --persona <persona id> --count 5` lets a model write scenarios for the agent and save them. The command shows each scenario when Yaksh saves it. Then it writes the generation with its status and its scenarios. If you stop the command, the generation stops, and the scenarios that it saved stay. Refer to [Scenario generation](/docs/scenario-generation).
- `yaksh agent update <agent id> --rules-file rules.yaml` sets the rules of the agent from a YAML or JSON list. The list replaces all rules of the agent. `yaksh agent view` shows the rules.

## Do a test of an agent

```sh
yaksh run start --agent <agent id> --all --wait
```

This command starts a run of all scenarios of the agent, waits until the run stops, and then waits for the verdicts of the judges. With `--wait`, the command exits with 0 only if all conversations of the run completed and the judges passed all calls. For a conversation that has retries, only the last retry counts. The judges decide each call by its scenario verdict after the labels of persons, as for the pass rate of the run. A call that did not connect, a call that the judges failed or did not score, and a failed evaluation give exit 1. A call where no caller talked, because the persona's voicemail or call screener answered, has no scenario verdict: its deciding agent rules decide it. If no `--timeout` is set, the wait for the judges stops after 10 minutes. If the judges are off, exit 0 does not tell you that the agent did its tasks correctly. If you stop the command with Ctrl-C while the run continues, the CLI cancels the run. `yaksh agent list` shows the IDs of the agents.

To do a test of how an outbound agent handles a voicemail or a call screener, add `--answer`. Each answer is a different conversation of each scenario:

```sh
yaksh run start --agent <agent id> --all --answer voicemail --answer screener --wait
```

If the judges failed a call, these commands show why:

- `yaksh run metrics <run id>` shows the pass rate, the coverage, the calls of each scenario with their verdicts, and the counts of each criterion. A call with a null verdict is a call whose evaluation failed. `unplayed` lists the calls where no caller talked, with their verdicts from the agent rules.
- `yaksh conversation evaluation <conversation id>` shows the verdicts of one call, and each criterion and rule with the quotes and the reasoning of its judge.
- `yaksh conversation view <conversation id>` shows the transcript of the call.

The instruction adherence judge reads the `config` of the agent in Yaksh. After you change the prompt or the flow of the agent, update this copy with `yaksh agent update <agent id> --config-file prompt.md`.

To add an agent from a Plivo CX agent download (the `{name}-config.json` file from the Plivo CX console), use this command:

```sh
yaksh agent import front-desk-config.json --brief "Books dental appointments for callers." --number +14155550100
```

Yaksh takes the name, the agent ID and the languages from the file, and keeps the whole file as the config. The draft leaves out a language code that Yaksh does not know and names it in `language_note`. If the file has no language that Yaksh knows, the command adds no agent. Without `--brief` and `--number`, the command shows what Yaksh reads from the file and adds no agent. In the console, choose **Import from a JSON file** on the **New agent** page.

`yaksh guide` shows how a coding agent uses the CLI to do tests of a voice agent. The same text is the skill in `cli/skill/yaksh/SKILL.md`. To add the skill for all your projects, use `npx skills add plivo-labs/yaksh -g`. Without `-g`, the skill goes only into the project in the current folder.

`yaksh --help` and `yaksh <command> --help` show all commands and flags.

## Run a suite

```sh
yaksh suite run <suite id> --wait
```

This command starts one run for each entry of the suite, waits for the calls and for the judges, and writes the suite run. It exits with 0 only if the suite run passed. `yaksh suite list` shows the IDs of the suites. Refer to [Suites in CI](/docs/suites#suites-in-ci).

## Phone numbers

```sh
yaksh numbers list --owner test
```

This command shows the test numbers and their state: `in_use`, `resting` or `ready`. Without `--owner`, it shows all numbers of the Plivo account. The owner of a number is `test`, `free`, `cx_agent`, `other` or `no_voice`. `problem` tells why no test can get a number now.

- `yaksh numbers use <number>` makes a free number a test number. Give the number with its country code, for example `+14155550100`.
- `yaksh numbers stop <number>` stops the use of a test number. Yaksh refuses while a test uses the number, or while the number rests after a test.
- `yaksh numbers refresh` reads the numbers of the account again now.
- `yaksh numbers account` shows the receiving application and its problems.

Refer to [Phone numbers](/docs/configuration#phone-numbers).
