---
title: Troubleshooting
description: Find the cause when a test call fails.
---

Open the conversation in the console. The page shows the status, the end reason and the failure reason. **Events** lists each event of the call with its time. For the meaning of these values, refer to [Results](/docs/results).

To read the log of the worker, use this command:

```sh
docker compose -f docker/compose.yaml logs worker
```

## The API rejects the conversation

| Message | Cause and action |
| --- | --- |
| `phone calls are off: add the Plivo Auth ID and Auth token in Settings` | Save the Plivo Auth ID and Auth token on the **Phone** tab of Settings. |
| `phone calls are off: set YAKSH_PUBLIC_URL to the address Plivo can reach` | Set `YAKSH_PUBLIC_URL` in `docker/.env`. Then make the API and worker containers again. |
| `the caller needs the ... key; add it in Settings` | Save the key that the message names on the **Providers** tab of Settings. |
| `phone calls are off: choose the receiving application in Settings` | Choose the receiving application on the **Phone** tab of Settings. Refer to [Phone numbers](/docs/configuration#phone-numbers). |
| `phone calls are off: choose test numbers on the Numbers page` | The receiving application has no numbers. On the **Numbers** page, click **Use for tests** on a free number. |
| `outbound tests are off: ...` | The outbound setup is not complete. The **Numbers** page shows the cause. Refer to [Outbound agents](/docs/outbound-agents). |

## The conversation stays queued

- No worker operates. Read the log of the worker.
- No test number is free. Each phone conversation uses one test number until it stops. The **Numbers** page shows the test numbers and their state. To add test numbers, click **Use for tests** on free numbers.
- The worker stopped when it started. If its log shows `the caller needs`, set the keys that the log names.

## The call fails

| Failure reason | Cause and action |
| --- | --- |
| `Plivo reported nothing about the call; is YAKSH_PUBLIC_URL reachable from Plivo?` | Plivo sent no report about the call. Possibly, Plivo cannot get to `YAKSH_PUBLIC_URL`. Examine the tunnel and the value. |
| `the agent answered but its audio stream never reached the worker` | The WebSocket connection to the worker failed. The public URL must pass WebSocket connections. |
| `the agent did not answer: ...` | The agent did not answer the call. Examine the number of the agent. |
| `phone calls are off: ...` | The worker does not have the phone variables. Set them. Then make the worker container again. |
| `the caller's model failed: HTTP 429 ...`, `the caller's model refused its last request: ...`, or a reason with `rate limit` | The LLM provider refused the caller's model, most often for a rate limit. The caller waits and asks again up to four times. A call that ends before the model answers is invalid, and the run tries it again if the run has retries left. Lower **Phone calls at once** or **Text conversations at once** (Settings, **Limits** tab), or get a higher limit from the provider. If the judges use the same model, **Evaluations at once** and **Judge calls at once** add to the same limit. |

If the log of the worker shows `refused an unsigned request`, the worker could not verify the Plivo signature of a request. Make sure that `YAKSH_PUBLIC_URL` is the URL that Plivo uses, and that the Plivo Auth token in Settings is the token of the account. After a change of `YAKSH_PUBLIC_URL`, make the API and worker containers again. A change in Settings applies at once.

## Outbound tests

- `trigger_failed`: the `trigger_sent` wire event shows the HTTP status of the trigger, or why Yaksh did not send it.
- `no_call`: the agent did not call during its dial window. Examine the number that the agent called, and the calling numbers of the agent.

## Log of a correct worker

When a worker with a correct setup starts, its log shows these lines:

- `plivo server listening on port 8770`
- `checked N numbers of the Plivo account`
- `outbound tests: application <name> sends calls here`

The worker writes `checked N numbers of the Plivo account` again after each check that it does. If the log shows `keeping the stored numbers: ...`, the check failed, and Yaksh uses the numbers of the last check. The **Numbers** page shows the error. Examine the Plivo Auth ID and Auth token in Settings.
