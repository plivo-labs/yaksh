---
title: Writing criteria
description: How to write a criterion that a judge can decide from the call.
---

A criterion is one check on one call of a scenario. A judge model reads the call's transcript and decides whether the agent did what the criterion asks. Yaksha judges every criterion as written. It does not check the wording, so a badly written criterion gives poor verdicts.

## What a judge can see

Yaksha tests the agent from the outside, through a phone line. The judge reads only what Yaksha observed.

| The judge sees | The judge does not see |
| --- | --- |
| What Yaksha's caller said, and whether its audio is confirmed as played | What the agent's speech recognition heard |
| Yaksha's transcript of the agent's audio | Tool calls, tool results and saved records |
| Who hung up, the end reason and the call length | Transfers, other than what the caller heard |
| The scenario: its instructions and the facts the caller knows, and for an agent that places the call, the data sent to it | The prompt the agent really ran |
| Today's date and the time zone of the test | Tone, pronunciation and pace: the judge reads text |

## Rules

1. Write what the agent says or does on the call. A condition inside the agent ("after the PIN matches") cannot be seen. Write it as speech: "if the agent says the PIN matched".
2. Write one check per criterion. Two checks in one criterion give one verdict for both.
3. Give exact values when they matter: "$95", not "the right price".
4. Write a condition when the check does not apply to every call: "If the caller asks about the price, the agent says...". A call where the condition does not come up is not applicable, not a fail.
5. Do not check a saved record. A criterion that needs a tool call or a backend state ends "unsure" with the kind "hidden action". It counts as not applicable and never passes on a guess.
6. Do not name a cause that the call cannot show, such as "the agent misheard".
7. Use an agent rule for a check that applies to every call of the agent, and a phrase rule for an exact phrase. A phrase rule is checked in code: it is cheaper and exact.

## Examples

| Criterion as written | Problem | Better wording |
| --- | --- | --- |
| After the date of birth matches the record, the agent books. | The match happens inside the agent. | The agent asks for the date of birth before it books. |
| The agent sounds friendly. | Tone is audio; the judge reads text. | The agent thanks the caller before the call ends. |
| The appointment is saved in the clinic's calendar. | Needs a saved record: unsure, hidden action. | The agent tells the caller the date and time of the booking. |
| The agent transfers the caller to billing. | The judge sees what the caller heard, not a transfer event. | The agent says it will transfer the call to billing, and then a different voice answers. |
| The agent does not invent prices. | Too general to judge on one call. | Upload the price list for the hallucination judge, or write the value: If the caller asks about the price, the agent says that a new patient cleaning costs $95. |
| The agent misheard the caller's name. | Names a cause the call cannot show. | The agent reads the caller's last name back as Lee. |
| The agent says the order number 48213. | An exact value. | Keep it, or make it a phrase rule on the agent. |
| The agent never says the caller's date of birth. | Applies to every call of the agent. | Make it an agent rule and leave it out of the scenario. |

## Numbers, dates and times

The judge's quotes are checked against the transcript in one written form for numbers, dates and times. So "five five five" in the transcript matches "555" in a quote, and "two thirty p.m." matches "2:30 pm". A criterion can give a value in either form.
