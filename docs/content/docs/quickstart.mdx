## Before you start

You must have:

- Docker with Docker Compose 2.24 or later.
- An account with Plivo and OpenAI, a speech-to-text provider (for example Deepgram), and a text-to-speech provider (for example ElevenLabs, which the built-in personas use).
- A voice number in your Plivo account that no Plivo application receives.
- A voice agent with a phone number.

## Start Yaksh

1. Get the code:

   ```sh
   git clone https://github.com/plivo-labs/yaksh.git
   cd yaksh
   ```

2. Make the configuration file:

   ```sh
   cp docker/.env.example docker/.env
   ```

3. In `docker/.env`, set `YAKSH_API_TOKEN` to a secret value. Clients send this token to the API.
4. In `docker/.env`, set `YAKSH_ENCRYPTION_KEY`. It encrypts the keys that you save in Settings. To make one, run `openssl rand -base64 32`. Keep a copy of it: without it, Yaksh cannot read the saved keys.
5. Start Yaksh:

   ```sh
   docker compose -f docker/compose.yaml up
   ```

   Docker gets the image of the newest Yaksh release. Do not stop this command. Do the next steps in a second terminal. If you stop this command, all the containers stop.

6. Open the console at http://localhost:8000. Enter the value of `YAKSH_API_TOKEN`.
7. The console opens on **Settings**. Add the LLM provider key, the speech-to-text key, the text-to-speech key, and the Plivo Auth ID and Auth token. Yaksh checks each key with its provider before it saves it. Refer to [Configuration](/docs/configuration).

The API is at `/api/v1`. Send the token in the `Authorization` header as a bearer token. If a request fails, the body of the response is `{"error": {"code": "...", "message": "..."}}`. For a validation error, `error` also has `details`.

## Connect Plivo to the worker

Plivo sends the call audio to the worker. Thus, the worker must have a public HTTPS URL. Yaksh cannot make phone calls until you set this URL.

1. Make a public HTTPS URL that goes to port 8770 of the worker. The URL must also accept WebSocket connections. For example, use a [Cloudflare named tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/). If cloudflared operates on your computer and not in a container, point your hostname to `http://localhost:8770`.
2. In `docker/.env`, set `YAKSH_PUBLIC_URL` to this URL.
3. Make the API and worker containers again. The API and the worker read `YAKSH_PUBLIC_URL` only when they start. In `docker/compose.yaml`, the API service has the name `yaksh`.

   ```sh
   docker compose -f docker/compose.yaml create --force-recreate yaksh worker
   docker compose -f docker/compose.yaml start yaksh worker
   ```

4. In the console, open the **Phone** tab of Settings. Click **Make application**. Yaksh makes a Plivo application that sends calls to the worker.
5. On the **Numbers** page, click **Use for tests** on your number. Yaksh calls from its test numbers only. Refer to [Phone numbers](/docs/configuration#phone-numbers).

With `docker/compose.dev.yaml`, `scripts/tunnel.sh` opens a quick tunnel. Refer to [Development](/docs/development).

## Make a test call

You can do these steps in the console or with the API. The commands below use the API.

1. In your shell, set `YAKSH_API_TOKEN` to the same value as in `docker/.env`.
2. Get the built-in personas:

   ```sh
   curl localhost:8000/api/v1/personas -H "Authorization: Bearer $YAKSH_API_TOKEN"
   ```

   Copy the ID of one persona.

3. Add your agent with its phone number and a brief of at least 20 characters:

   ```sh
   curl -X POST localhost:8000/api/v1/agents \
     -H "Authorization: Bearer $YAKSH_API_TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"name": "Support line", "agent_number": "+14155550100", "brief": "Answers billing questions and resets passwords."}'
   ```

4. Add a scenario that uses the persona:

   ```sh
   curl -X POST localhost:8000/api/v1/agents/<agent id>/scenarios \
     -H "Authorization: Bearer $YAKSH_API_TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{
       "name": "Book a table",
       "persona_id": "<persona id>",
       "instructions": "You want a table for two tonight. Once the agent confirms the booking, say goodbye.",
       "criteria": ["Reads the time and party size back before it books."],
       "data_sets": [{"name": "Priya", "known_facts": [{"name": "Name", "value": "Priya Raman"}]}]
     }'
   ```

5. Start a run of the scenario:

   ```sh
   curl -X POST localhost:8000/api/v1/runs \
     -H "Authorization: Bearer $YAKSH_API_TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"agent_id": "<agent id>", "scenarios": [{"scenario_id": "<scenario id>"}]}'
   ```

6. In the console, click **Conversations**. Then click the conversation.
7. Read the transcript. Then play the recording.

The wire events of the conversation show `connect_started`, `ringing`, `answered` and `connected` while the call starts.

A conversation uses the persona of its scenario.
