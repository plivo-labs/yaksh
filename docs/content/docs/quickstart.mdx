## Before you start

You must have:

- Docker with Docker Compose 2.24 or later.
- An account with Plivo, Deepgram, OpenAI and ElevenLabs.
- A voice number in your Plivo account.
- A voice agent with a phone number.

## Start Yaksha

1. Get the code:

   ```sh
   git clone https://github.com/plivo-labs/yaksha.git
   cd yaksha
   ```

2. Make the configuration file:

   ```sh
   cp docker/.env.example docker/.env
   ```

3. In `docker/.env`, set `YAKSHA_API_TOKEN` to a secret value. Clients send this token to the API.
4. In `docker/.env`, set the credentials of the services: `DEEPGRAM_API_KEY`, `ELEVENLABS_API_KEY`, `OPENAI_API_KEY`, `PLIVO_AUTH_ID` and `PLIVO_AUTH_TOKEN`. The file has example values. Replace each example value, or remove its line.
5. Start Yaksha:

   ```sh
   docker compose -f docker/compose.yaml up --build
   ```

   Do not stop this command. Do the next steps in a second terminal. If you stop this command, all the containers stop.

6. Open the console at http://localhost:8000. Enter the value of `YAKSHA_API_TOKEN`.

The API is at `/api/v1`. Send the token in the `Authorization` header as a bearer token. If a request fails, the body of the response is `{"error": {"code": "...", "message": "..."}}`. For a validation error, `error` also has `details`.

## Connect Plivo to the worker

Plivo sends the call audio to the worker. Thus, the worker must have a public HTTPS URL. Yaksha cannot make phone calls until you set this URL.

1. Make a public HTTPS URL that goes to port 8770 of the worker. The URL must also accept WebSocket connections. For example, use a [Cloudflare named tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/). If cloudflared operates on your computer and not in a container, point your hostname to `http://localhost:8770`.
2. In `docker/.env`, set `YAKSHA_PUBLIC_URL` to this URL.
3. Make the API and worker containers again. The API and the worker read `YAKSHA_PUBLIC_URL` only when they start. In `docker/compose.yaml`, the API service has the name `yaksha`.

   ```sh
   docker compose -f docker/compose.yaml create --force-recreate yaksha worker
   docker compose -f docker/compose.yaml start yaksha worker
   ```

With `docker/compose.dev.yaml`, `scripts/tunnel.sh` opens a quick tunnel. Refer to [Development](/docs/development).

## Make a test call

You can do these steps in the console or with the API. The commands below use the API.

1. In your shell, set `YAKSHA_API_TOKEN` to the same value as in `docker/.env`.
2. Get the built-in personas:

   ```sh
   curl localhost:8000/api/v1/personas -H "Authorization: Bearer $YAKSHA_API_TOKEN"
   ```

   Copy the ID of one persona.

3. Add your agent with its phone number and a brief of at least 20 characters:

   ```sh
   curl -X POST localhost:8000/api/v1/agents \
     -H "Authorization: Bearer $YAKSHA_API_TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"name": "Support line", "agent_number": "+14155550100", "brief": "Answers billing questions and resets passwords."}'
   ```

4. Add a scenario that uses the persona:

   ```sh
   curl -X POST localhost:8000/api/v1/agents/<agent id>/scenarios \
     -H "Authorization: Bearer $YAKSHA_API_TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{
       "name": "Book a table",
       "persona_id": "<persona id>",
       "goal": "Book a table for two tonight.",
       "known_facts": [{"name": "Name", "value": "Priya Raman"}],
       "criteria": ["Reads the time and party size back before it books."]
     }'
   ```

5. Start a run of the scenario:

   ```sh
   curl -X POST localhost:8000/api/v1/runs \
     -H "Authorization: Bearer $YAKSHA_API_TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"agent_id": "<agent id>", "scenario_ids": ["<scenario id>"]}'
   ```

6. In the console, click **Conversations**. Then click the conversation.
7. Read the transcript. Then play the recording.

The wire events of the conversation show `connect_started`, `ringing`, `answered` and `connected` while the call starts.

A conversation uses the persona of its scenario.
