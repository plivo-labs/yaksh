---
title: Languages
description: The languages of agents and callers, and how Yaksh hears a call.
---

An agent serves one or more languages. A persona, which is the caller, speaks a primary language and can have additional languages that it switches to during a call.

## Agent languages

Set the languages of an agent on its page, in order. The first language is the main language of the agent. English has a region: English (US), English (India), English (UK) or English (Australia). A new agent gets English (US).

An import takes all the languages of the agent from its provider. If the provider gives a code that Yaksh does not know, for example `multi`, the draft leaves it out and names it in `language_note`. Then you choose the languages.

## Caller languages

A persona speaks English, Hindi, Bengali, Gujarati, Kannada, Marathi, Tamil, Telugu or Spanish. A caller in an Indian language speaks the everyday mix, with common English words, as people talk on the phone. The caller says its fixed lines in English: the first words, the nudge when the agent is quiet, and the goodbye at the turn limit. Hindi has its own fixed lines.

The voice of a persona must speak its language. ElevenLabs' Flash and Multilingual models read Bengali, Gujarati, Kannada, Marathi and Telugu from the text, because they take no language setting for them, and these languages can sound less natural. ElevenLabs' v3 and v4 models take a language setting for every language. A voice's model is set when you add the voice.

A background speaker talks in the language of the persona. Only English and Hindi have their own clips; the other languages use the English clips.

To test an agent in more than one language, make one run for each language, with personas that speak it. **Mix personas** in the run dialog takes the personas of one language.

## A caller that switches languages

Give a persona additional languages to test how an agent handles a caller who changes language during a call. The primary language is the caller's main language. The caller says Yaksh's fixed lines in it, and the voice preview, the voicemail greeting and the background speaker use it.

Yaksh tells the caller its languages and to switch between them as its prompt and its instructions say. If they do not say when, the caller switches at least once. Say how the caller mixes its languages in the persona's prompt, for example "You switch to Hindi when you give numbers". Say when it switches in the scenario's instructions, for example "When the agent asks for your date of birth, answer in Hindi". Then write a criterion for what the agent must do, for example "After the caller speaks Hindi, the agent answers in Hindi".

Yaksh sets the speech-to-text and the voice once for the whole call:

- Deepgram uses `hi` when the agent answers only in English and Hindi, and `multi` for any other mix. Since 23 October 2026, Deepgram's hosted `multi` model hears all of Yaksh's languages. A self-hosted Deepgram can have the older `multi` model, which hears only English, Hindi and Spanish of Yaksh's languages.
- The other speech-to-text providers keep the setting of the primary language for the whole call. Speech in another language can then come out wrong.
- An ElevenLabs voice gets no language setting, so it reads the language of each reply from its text. A Nimble voice gets `auto`. A Sarvam, Cartesia or Azure voice keeps the primary language.

A phone run is refused when the speech-to-text does not hear, or the voice does not speak, one of the persona's languages, as for a persona of one language. Yaksh does not check how well a provider handles two languages in one call: choose the providers for the languages you test.

The caller check knows the persona's languages. A caller reply in another language, or a caller that never switches when it should, is a caller problem, so it does not count against the agent.

When you update to the first version of Yaksh with additional languages, finish the update before you give a persona additional languages. A worker of an older version cannot read such a persona.

## Phrase rules

A phrase rule checks the words of the agent as they are written. For an agent with more than one language, write the rule so that it matches in each language, for example a regular expression with the phrase in each: `thank you for calling|कॉल करने के लिए धन्यवाद`.

## How Yaksh hears the agent

Yaksh writes what the agent says with the speech-to-text provider in Settings. The agent should answer in the language of the persona. If the agent does not serve that language, it should answer in its main language. Each provider hears these languages:

| Provider | Hears |
| --- | --- |
| Deepgram (`nova-3`) | All of Yaksh's languages |
| Sarvam (`saaras:v4`) | All but Spanish |
| AssemblyAI (`universal-3-6-pro`) | English, Hindi, Marathi and Spanish |
| Soniox (`stt-rt-v5`) | All of Yaksh's languages |
| Gladia (`solaria-1`) | All of Yaksh's languages |

A phone run is refused when the provider does not hear the language that the agent should answer in. Every provider except Deepgram hears that one language. Deepgram uses one language setting for each call, chosen from the languages of the agent and the language of the persona:

1. The agent should answer in the language of the persona. If the agent does not serve that language, it should answer in its main language.
2. From the settings that hear that language, Yaksh uses the one that hears the most of the other languages of the call. On a tie, a model for one language comes first.

| Setting | Hears |
| --- | --- |
| One language, for example `en-IN`, `hi` or `ta` | That language |
| `hi` | Hindi, and the English words in Hindi speech |
| `mr` | Marathi and Hindi, but not English |
| `multi` | English, Hindi and Spanish, and 7 languages that Yaksh does not have |

For English, Yaksh uses the English variant of the agent. The call page shows the setting after the speech-to-text model, for example `nova-3 (hi)`.

No setting hears English together with Bengali, Gujarati, Kannada, Tamil or Telugu. For an agent that serves English and one of these, the call uses the model of the language that the agent should answer in. When a reply is in a language that the setting does not hear, the transcript of that reply is wrong, and the judges read the wrong transcript.
