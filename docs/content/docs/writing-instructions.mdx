---
title: Writing instructions
description: How to write the instructions that tell the caller what to do on a call.
---

The instructions of a scenario tell Yaksh's caller what to do on the call. The caller reads them with the facts and the persona, and nothing else. It never sees the criteria. Scenario generation writes instructions that follow this page, and you can write or change them yourself.

Yaksh does not check the instructions. Text that breaks these guidelines still runs, but the calls are less stable and the results are harder to trust.

## What goes where

| Put this | In |
|---|---|
| What the caller wants, and how it reacts to the agent | The instructions |
| Names, numbers, dates, codes and other values | The facts the caller knows |
| Values the caller does not have | The facts the caller does not have |
| Mood, personality and way of speaking | The persona |
| What the agent must say or do | The criteria |

## Guidelines

- **Write to the caller as "you".** For example: "You want to move your appointment."
- **Start with what the caller wants.** One sentence is enough.
- **Write reactions, not numbered steps.** The agent can ask in any order, so write each line as "When the agent asks for …, …" or "If the agent offers …, …". A numbered list makes the caller say things before the agent asks for them.
- **Give each choice.** Say what the caller picks, and what it does when the first choice is not possible.
- **Name values by their fact.** A value that the caller gives the agent, such as a name, number, date or code, goes in the facts. Write "give your date of birth", and put the date in the facts. The caller never invents a value, so a value that is not in the facts makes the call stall. Counts and limits that steer the caller, such as "ask at most twice", stay in the instructions.
- **Keypad entry is a fact too.** On a phone call, the caller presses the keys of a value when the agent asks it to type or enter the value on the keypad, so put the value in the facts and write "When the agent asks you to enter your card number on the keypad, enter it."
- **Make the end clear.** Say when the caller's part is over, for example "Once the agent confirms the new time, say goodbye.", "If the agent refuses twice, end the call." or "Let the agent end the call." The caller ends the call only when its instructions are done, or at the point where they tell it to end, and only when the agent's latest turn shows that point. Most calls end when the agent ends them. The turn limit and the call length limit stop the other calls.
- **Leave out mood and language.** The persona gives them, so the same scenario can run with another persona.
- **Test one complication.** One mistake or one unusual request for each scenario.

## Example

Instructions:

> You want to move your dentist appointment to a weekday morning. When the agent asks for your details, give your name and date of birth. If no weekday morning is free, take the first afternoon that it offers. Once the agent confirms the new time, say goodbye.

Facts the caller knows: Name: Priya Raman. Date of birth: 14 March 1988.

Criteria: "Asks for the caller's date of birth before it changes the appointment." "Reads back the new day and time."

## Messy input

To test how the agent handles a mistake, say exactly what the caller gets wrong first and when it corrects it:

> When the agent asks for your date of birth, give your wrong date of birth first. When the agent reads it back, correct it to your date of birth.

Facts the caller knows: Date of birth: 14 March 1988. Wrong date of birth: 14 May 1988.
