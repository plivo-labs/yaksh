---
title: Interruptions
description: The caller says a fixed line while the agent speaks.
---

A scenario can make Yaksh's caller interrupt the agent: the caller says a fixed line while the agent still speaks. Use interruptions to test if the agent stops when a caller talks over it, and what it says next.

Interruptions play on phone calls only, while the persona is on the call. A text run has no interruptions. A call that the persona's voicemail answers has none. The time before the persona picks up after its call screener has none.

## Write interruptions

A scenario has up to 3 interruptions. Write them in the file of `yaksh scenario create` or `yaksh scenario update` (refer to [CLI](/docs/cli)), or send them with the API. The console does not show them yet. A scenario that you save in the console keeps its interruptions.

```yaml
interruptions:
  - agent_says: new patient
    say: "Sorry, how much does that visit cost?"
  - after_s: 3
    say: "Hold on, can you say that again?"
```

| Field | Meaning |
| --- | --- |
| `say` | The caller's words, 1 to 200 characters. A `{{Fact name}}` placeholder takes the value of the data set. The limit applies before and after the data set fills in the placeholders. |
| `agent_says` | A phrase of 1 to 200 characters, with at least one word or number. It can have `{{Fact name}}` placeholders. |
| `after_s` | The wait in seconds, from 0 to 30. The default is 0 with a phrase, and 2 with no phrase. |
| `from_answer` | The first answer of the agent that can start a wait, from 1 to 100. The default is 1 with a phrase, and 2 with no phrase, which skips the greeting. |

A wait starts each time the agent says the phrase. With no phrase, a wait starts when each answer of the agent starts. Answer 1 is the first speech of the agent, often its greeting. The next answer starts after the caller replies or presses keys. An interruption line does not start an answer.

## When a line plays

- A line with a phrase plays when its wait ends and the agent still speaks in the turn in which it said the phrase.
- A line with no phrase plays in the agent turn of the same answer that is open when its wait ends. This can be a later turn of the answer. If the agent pauses at that time, the line plays when the agent speaks again in that turn.
- The agent cannot cut the line.
- Each line plays one time at most, and one line plays at a time.
- A wait that does not play its line is a try with a reason. The line can play at a later wait. The reasons are in the table in [Results](#results).

## Phrases

- A phrase matches whole words only: "fee" does not match "coffee", although a phrase rule finds it there.
- As in a phrase rule, numbers, dates and times match in words or in digits. Number words match their digits: "first visit" also matches "1st visit" and "one visit". Digits do not join across punctuation: "five five five, oh one four two" does not match "5550142".
- A wait starts when the speech-to-text gives the phrase, a short time after the agent says it. The speech-to-text can still add to a number at the end of the words. Thus a phrase that ends with a number matches when a word or a punctuation mark comes after the number.
- A phrase needs the words of the agent while it speaks. Deepgram, AssemblyAI and Soniox give partial words. Gladia gives words only at short pauses, at most 5 s apart, so its waits can start later. Sarvam gives the words only after the agent stops, so a run start refuses a scenario with a phrase when Settings use Sarvam. A line with no phrase works with all providers.

Yaksh makes the speech of each line with the voice of the persona when the call starts. A line whose speech failed does not play.

## What the caller does next

The model of the caller learns that it said the line, after the agent turn that the line interrupted. An agent turn that starts while the line plays is part of the speech that the line interrupted. When the line has played and no agent turn is open, the caller acts:

- The agent stopped within 2 s of the first sound of the line and did not speak again in that speech: the caller waits for the agent. It replies to the next agent turn in which the agent speaks. If 3 s pass with no agent turn open, the caller continues the call. Late words of the speech that the line cut are no answer.
- The agent stopped and then spoke again in that speech: the caller replies to it.
- In all other cases, for example when the agent talked over the line, the caller replies to the speech as usual.

The agent stopped when its voice was quiet for at least 0.6 s. A quiet at the end of its last turn becomes a stop when it lasts 0.6 s. A shorter pause, such as a pause between two sentences, is not a stop. This is also true when the VAD stop in Settings is shorter.

The caller keeps to its known facts. A line can give a value that differs from them, such as a new age. That line does not change the facts, and the caller can take the value back later. Write lines that ask something or that ask the agent to wait.

A line that asks the agent to wait, such as "Sorry, one moment.", works when the agent stops for it. When the agent then says that it will wait, the caller says that it is back and continues. The agent can talk over the line and say later that it will wait. Then the caller can wait too. After 15 s of silence, the caller asks the agent a question.

Backchannel lines, such as "Mm-hmm.", are not supported yet. Yaksh handles them as other lines: when the agent stops for one and says nothing more, the caller waits 3 s before it continues.

## Results

- The transcript shows each line as a caller turn with the badge **Fixed line**. The first words, the question when the agent is silent and the goodbyes have the same badge. In the API, the turn of a line has `interruption`: the number of the interruption. The line comes after the agent turn that it interrupted, because that turn stays whole.
- The judges see where each line came. After the turn of the line, a note in parentheses tells them where the caller spoke: how far into which agent turn, and after which words of the agent. The part of their view about the caller's test also lists the lines that played. Thus the check of the caller counts them as part of its test. The judges judge the call as they judge all other calls.
- Nothing checks yet how fast the agent stopped. To check what the agent did after a line, write a criterion with the value that you expect. An example is "The agent says that a new patient visit costs $95." Refer to [Writing criteria](/docs/writing-criteria).
- The recording in the **Audio** card of the call has the two sides, the agent on the left and the caller on the right. Listen to it to hear how the agent stopped.
- The lines count in the speech of the caller (**Agent's share of the speech**). They do not count in **Agent response time**, **Longest wait** or **Spoke over the caller**, because the caller said them over the agent. Thus **Spoke over the caller** does not show an agent that talked over a line.
- Yaksh saves each try with the conversation. A try is a wait that ended while the line could still play, or a line that can never play. The API returns the tries in the conversation's `wire_events`, with the kind `interruption` and the try in the field `interruption`. The **Events** card of the call shows each try with its line number and its outcome.

A try that played has no `reason`. Each other try has one of these reasons:

| Reason | Why the line did not play |
| --- | --- |
| `turn_ended` | The agent's turn ended before the wait ended. With no phrase: no agent turn of the answer was open when the wait ended. |
| `agent_quiet` | With a phrase: the agent was quiet when the wait ended. With no phrase: the agent's turn ended before the agent spoke again. |
| `caller_speaking` | The caller was speaking. |
| `key_press` | The caller pressed keys in this agent turn. |
| `other_line` | Another line was playing, or its 2 s window was open. |
| `call_ending` | The call was ending, or it ended during the wait. |
| `audio_not_ready` | The speech of the line was not ready yet. |
| `audio_failed` | Yaksh could not make the speech of the line, and the `detail` of the try tells why. The line never plays. |
| `no_words_while_speaking` | The speech-to-text in Settings gives no words while the agent speaks, so the phrase can never start a wait. |
